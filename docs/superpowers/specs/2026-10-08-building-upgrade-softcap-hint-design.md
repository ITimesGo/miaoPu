# 建筑升级副文案：软帽增量提示 — 设计

日期：2026-10-08  
状态：已定稿（待实现）  
前置：`2026-10-08-building-scaled-soft-caps-design.md`（软帽绑定与数值表）

## 目标

商店「建筑」分页里，升级/建造条目的 `desc` 附带**真正会上涨**的库存软帽增量，玩家点购前即可看到上限收益。

## 非目标

- 不改 HUD 资源色、升级扣费、软帽数值表本身。  
- 不做升级后的 toast / 日志反馈。  
- 不改粮仓修缮文案（修缮不影响软帽）。  
- 不在商店单独加一行 UI（仍拼进现有 `desc`）。

## 已确认决策

| 项 | 选择 |
|----|------|
| 位置 | 商店条目副文案（`ShopAction.desc`） |
| 数字格式 | 只写增量（`玩具 +4`） |  
| 标签 | 全称（玩具/零食/知识/鱼肉/药品/矿石/木材/金库） |
| 金库不变时 | 不提金库（不写 +0、不写说明句） |
| 实现 | `economy.ts` 提供对比文案；`shop.ts` 拼进 `desc` |

## API

在 `src/game/data/economy.ts` 新增：

```ts
softCapDeltaHint(before: SoftCapBuildings, after: SoftCapBuildings): string
```

行为：

1. 对下列键用现有 `softCapFor` 对比前后：`toy` `snack` `knowledge` `fish` `medicine` `ore` `wood`。  
2. 另用 `coinSoftCap` 对比金库。  
3. 仅当 `after - before > 0` 时输出一项。  
4. 标签用全称（与 HUD Pill 一致）：`玩具` `零食` `知识` `鱼肉` `药品` `矿石` `木材` `金库`。  
5. 连接符：` · `，形如 `玩具 +4 · 零食 +4 · 知识 +8 · 金库 +600`。  
6. 无任何上涨 → 返回 `''`。

顺序固定为：玩具 → 零食 → 知识 → 鱼肉 → 药品 → 矿石 → 木材 → 金库（缺项跳过）。

## 商店拼接

`getShopActions`（`shop.ts`）在生成建筑项时：

1. 构造 `before` = 当前四建筑等级（粮仓未建为 `0`）。  
2. 构造 `after` = 浅拷贝 `before`，仅把该项对应建筑的等级改为升级/建造后的值。  
3. `hint = softCapDeltaHint(before, after)`。  
4. 若 `hint` 非空，在原有 `desc` 后追加 ` · ${hint}`。

| 项 | `after` 变化 | 保留原有文案 | 软帽 hint 预期 |
|----|--------------|--------------|----------------|
| 升级小屋 | `cottage +1` | `Lv.a→b · 猫口 N` | 玩具/零食/知识；金库仅当 `max(cottage,harbor)` 抬高时 |
| 升级港口 | `harbor +1` | `Lv.… · 码头扩大 · 商船更常来` | 鱼肉；金库同上规则 |
| 升级货船 | `boat +1` | `Lv.… · 船只变大` | 药品 |
| 建粮仓 | `granary: 0→1` | `容量 …` | **通常为空**（矿石/木材未建已按 Lv1 基线，建到 1 不涨软帽） |
| 升级粮仓 | `granary +1` | `Lv.… · 容量 N` | 矿石、木材 |
| 修缮粮仓 | 不变 | 原样 | 不加 hint |

猫口、小麦硬容量仍用现有文案（绝对值或现有写法），不改成增量，避免和软帽增量混格式。

## 说明书

`manual.ts`「建筑升级」或「资源」段补一句：商店建筑项会显示库存软帽增量（有涨才写）。不手写具体数字。

## DevToolbar

无新状态字段；不强制加控件。若边测需要可在实现计划里可选加「打印当前 hint」类按钮——默认不做。

## 验证

- 单元/脚本级：同一 `before/after` 得到固定 hint；金库被更高建筑压住时字符串不含「金库」。  
- 小屋 1→2 且港=1：含玩具/零食/知识/金库增量。  
- 小屋 1→2 且港≥2：含玩具/零食/知识，**不含**金库。  
- 粮仓 0→1：hint 为空（仅容量文案）。  
- 粮仓 1→2：含矿石、木材增量。  
- `edge-flows` 或等价断言覆盖上述；`npm run build` 通过。

## 风险与注意

- `desc` 变长：现有商店副文案已用小字换行，可接受；勿再拆第二行 UI。  
- 数字必须来自 `softCapFor` / `coinSoftCap`，禁止在 `shop.ts` 手写软帽表。
